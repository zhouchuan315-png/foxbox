| 项目 | 内容 |
|---|---|
| 产品名 | FoxBox（环境隔离浏览器工作台） |
| 版本 | v0.1（MVP 定义） |
| 状态 | 草稿 |
| 日期 | 2026-11-19 |
| 目标平台 | macOS（Intel / Apple Silicon 优先），后续 Windows |
| 定位 | 本地优先、单机运行的多环境浏览器管理工具，对标 AdsPower 的核心能力子集 |

---

## 1. 背景与问题

同一台电脑登录多个业务账号时，平台会把"同一个浏览器环境"当作强关联信号：相同的 Canvas 指纹、相同的字体列表、相同的时区语言、相同的出口 IP。一旦被判定关联，轻则限流，重则连坐封号。

传统做法（无痕窗口、Chrome 多用户、切 VPN）解决不了问题，因为**底层指纹没变，只是 Cookie 分开了**。

FoxBox 要解决的是：**在一台机器上，为每个账号提供一套逻辑上独立、内部自洽、跨会话稳定的浏览器身份。**

### 1.1 三个必须同时成立的条件

任何一项缺失，隔离就失效：

1. **指纹独立**：每个环境有各自的 navigator、屏幕、WebGL、字体、音频特征
2. **存储独立**：Cookie / localStorage / IndexedDB 互不可见
3. **网络独立**：每个环境走各自的出口 IP，且 IP 归属地与指纹的地理信息一致

> 关键洞察：**一致性比唯一性更重要**。一个"Linux UA + Windows 字体 + 美国 IP + 中国时区"的环境，比不改还容易被识别。

## 2. 目标与非目标

### 2.1 本期目标（MVP）

- 单机管理 50+ 个浏览器环境，配置持久化
- 一键启动/关闭环境，每个环境独立窗口、独立存储、独立代理
- 指纹在环境创建时**固化**，此后每次启动保持一致（不漂移）
- 启动前做代理连通性与地理一致性预检，不一致则阻断
- 启动后做本地指纹自检，输出"配置值 vs 页面实际读到值"的差异报告
- 提供本地 HTTP API，供脚本批量操作

### 2.2 非目标（本期明确不做）

| 不做 | 原因 |
|---|---|
| 自研/编译浏览器内核 | 成本极高，本期用现成开源引擎 |
| 云同步、团队协作、权限体系 | 单机优先，先验证核心价值 |
| 内置代理销售或 IP 池 | 只做代理配置管理，不碰资源生意 |
| 移动端 / 安卓云手机 | 完全不同的技术栈 |
| RPA 可视化编排 | 先用脚本 + API 覆盖 |
| 破解平台风控、批量注册 | **明确禁止，见第 8 节** |

## 3. 用户与场景

### 3.1 目标用户

- 跨境电商运营：一店一环境，避免店铺关联
- 广告投放/媒体采购：多客户账号分环境管理
- 社交媒体运营：品牌号与个人号隔离
- 测试/QA：需要干净、可复现的浏览器环境做多地域验证

### 3.2 核心场景

**场景 A：新建并首次登录**
> 运营新建环境"店铺-US-01"，选择美国出口代理，系统生成一套自洽的美国 Windows 指纹。打开窗口，登录店铺后台，Cookie 落在该环境独立目录。关闭。

**场景 B：次日复用**
> 第二天重新打开同一环境。指纹、时区、语言、代理全部与昨天一致，平台看到的是"同一台设备回来了"，而不是"一台新设备"。

**场景 C：批量预检**
> 有 30 个环境要跑。先批量执行代理预检，把 5 个已失效的代理标红，避免带着坏 IP 启动污染账号。

**场景 D：脚本化操作**
> 用外部脚本调本地 API 启动环境，拿到自动化句柄，跑一段采集/巡检逻辑，结束后关闭环境。

## 4. 功能需求

优先级：P0 = MVP 必须；P1 = 首个可用版本；P2 = 后续迭代。

### 4.1 环境管理（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-01 | 创建环境 | 填写名称、选操作系统身份、选代理、选分组；创建后生成并**持久化**一份指纹配置 |
| F-02 | 环境列表 | 展示名称、分组、代理、状态（空闲/启动中/运行中/异常）、最后打开时间；支持搜索与按分组筛选 |
| F-03 | 编辑环境 | 可改名称、分组、备注、代理；**指纹字段创建后默认锁定**，修改需二次确认并提示"可能导致账号关联风险" |
| F-04 | 删除环境 | 二次确认；默认进回收站（软删除），可恢复；彻底删除时清理该环境的 user-data 目录 |
| F-05 | 分组管理 | 增删改分组，环境可在分组间移动 |
| F-06 | 批量操作 | 多选后批量启动、批量关闭、批量预检代理 |
| F-07 | 状态实时性 | 环境崩溃/被手动关闭时，列表状态在 3 秒内回到"空闲"并记录退出码 |

**F-01 细则**：创建时若用户只选"目标国家 + 代理"，系统应自动推导出该地区的时区、语言、地理坐标，而不是让用户手填。

### 4.2 浏览器启动与隔离（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-10 | 独立存储 | 每个环境使用独立 user-data 目录；A 环境登录的站点，B 环境必须显示未登录 |
| F-11 | 独立代理 | 每个环境的流量只走自己的代理；未配置代理时明确提示"将使用本机直连 IP" |
| F-12 | 指纹隔离 | 两个环境同时打开同一检测站点，读到的 UA / 屏幕 / WebGL / 时区应不同 |
| F-13 | 跨会话稳定 | 同一环境连续启动 3 次，指纹自检结果完全一致（逐字段比对） |
| F-14 | 并发控制 | 默认最大并发环境数可配置；超出时排队并提示，而不是静默失败 |
| F-15 | 异常回收 | 主程序退出时，拉起的所有浏览器进程一并关闭，不留孤儿进程 |

### 4.3 代理管理（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-20 | 代理 CRUD | 支持 HTTP / HTTPS / SOCKS5，填写主机、端口、账号、密码 |
| F-21 | 密码加密存储 | 密码不以明文落库；使用系统钥匙串派生的密钥加密 |
| F-22 | 连通性检测 | 单条/批量检测，返回出口 IP、归属国家、延迟；失败给出错误原因 |
| F-23 | 地理一致性预检 | 启动前比对"代理出口国家"与"环境指纹期望国家"，不一致则阻断启动（可配置为仅警告） |
| F-24 | 失效标记 | 连续检测失败 3 次的代理标记为"疑似失效"，列表中高亮 |

### 4.4 指纹自检（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-30 | 本地自检 | 环境启动后，在空白页内采集 UA、platform、语言、时区、屏幕、硬件并发数、WebGL 渲染器、`navigator.webdriver`，与配置逐项比对 |
| F-31 | 差异报告 | 输出三态结果：一致 / 不一致 / 未覆盖；不一致项高亮并说明预期值与实际值 |
| F-32 | 第三方复核（P1） | 可一键在环境内打开公开检测站点，供人工复核 |

> F-30 是产品质量的生命线：**永远以页面实际读到的值为准，而不是以你写进配置的值为准。**

### 4.5 自动化接口（P1）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-40 | 本地 HTTP API | 仅监听 `127.0.0.1`，提供环境列表、启动、关闭、状态查询 |
| F-41 | 鉴权 | 首次启动生成随机 Token，请求需携带；Token 可在设置中重置 |
| F-42 | 脚本执行 | 支持向运行中的环境提交一段 Playwright 脚本并返回执行结果（M10 落地，见 §4.13） |
| F-43 | 端口暴露 | 每次启动返回自动化连接信息；Chromium 引擎提供 CDP 端点，Firefox 引擎提供进程内句柄 |

**F-43 说明（2026-11-21 更正）**：Camoufox 基于 Firefox，不提供 CDP 端点（硬限制，见技术文档 6.3）。
更关键的是：Camoufox 的 `launchServer()` **明确不支持 persistent context**，而我们的环境全是
persistent —— 所以「把已启动的环境挂成 ws 端点让外部连」这条路在本引擎上不成立，
不能靠伪造一个 `cdp` 字段糊过去。外部自动化的正式形态改为 **HTTP 脚本执行**（§4.13）。

### 4.6 定时与事件触发（M5 已实现）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-60 | 定时规则 | 标准 5 段 cron；录入时校验，并实时预览"接下来三次"；到点把关联任务推出去 |
| F-61 | 错过不补跑 | 服务未运行期间错过的触发，重启后只记一条「跳过」，不集中补执行 |
| F-62 | 不叠加 | 同一规则上一次任务还在跑时，本次触发标 `skipped`，不排队、不并发 |
| F-63 | 事件钩子 | 定期巡检代理；连续失败达到阈值时执行动作：切备用代理 / 关闭相关环境 / 跑任务 / 仅记录 |
| F-64 | 指纹一致性守卫 | 自动切代理只在出口国家相同时执行；国家不同则不动，并把原因写进记录 |
| F-65 | 触发可查证 | 每次事件留一条记录（触发方式、结果、人话说明）；巡检无异常不写历史 |

**F-61 说明**：定时任务最常见的坑不是"没跑"，而是"重启后一口气补跑"。补跑会让同一批
环境在几分钟内被反复启停，副作用远大于漏掉一次。所以选择明确地"少跑"，并且把这件事
记在历史里——让用户看见系统当时不在，而不是以为它一直在跑。

**F-64 说明**：指纹里的时区与语言是按出口国家固化的。换到另一个国家的代理，
环境会变成"IP 在美国、时区在亚洲"，这比"代理挂了"更难解释，通常要等到站点风控才暴露。
所以自动切换把"同国家"作为硬前提，不满足就不动，而不是"先切过去再说"。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-88 | 任务级超时 | 单任务可设 `timeoutMs`，超时后整任务中止并落 `error_class = timeout` |
| F-89 | 分类重试 | 只重试瞬时错误（超时/连接断/崩溃），且只重跑失败的目标；配置类错误不重试 |

### 4.12 身份健康（M9 已实现）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-92 | 启动自检标记 | 手动启动时比对预设与页面实测（含 `window` 尺寸）；不一致只打标，不阻断启动 |
| F-93 | 跨平台屏幕探测 | macOS / Linux / Windows 各自解析主屏逻辑分辨率；探测失败保持原尺寸而不猜 |

> F-92 的「只标记不修复」是实测结论，不是偷懒：改 `fingerprint.screen` 会让
> `mediaDevices` / `locale` / `timezone` 等 11 个键跟着重抽（见 [MVP2 §4.5.1](./MVP2.md)），
> 那等于把环境变成另一台设备。老环境的正确处置是重建，不是局部修补。

### 4.13 外部自动化（M10 已实现）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-94 | 连接信息 | `GET /api/profiles/:id/automation` 返回引擎、运行态、可用调用方式；**没有 CDP 时明确说明原因**，不给空字段让人猜 |
| F-95 | 外部脚本执行 | `POST /api/profiles/:id/run-script`：`page`（页面表达式）与 `playwright`（async 函数体，形参 page/ctx）两种模式；支持超时、按需自动启动、执行后截图；脚本报错返回 422 + `ok:false`，不吞成 500 |
| F-96 | 可复制示例 | 接口返回带 token 的 curl / Python / Node 片段，界面「自动化」页可直接复制、可试跑 |

**为什么不是 CDP**：Firefox 走 Juggler，没有 CDP；Camoufox 的 `launchServer()` 又不支持
persistent context。与其让外部工具连一个不存在的端点，不如把脚本执行做成 HTTP：
调用方不需要 Node、不需要知道协议，只要 `POST` 一段 async 函数体。

**信任边界**：脚本在服务进程内执行，等同 `POST /api/tasks` 的 `eval` 步骤——本地单用户工具，
接口本身要求 Bearer token。脚本正文不进审计，只记模式、耗时、字节数与结果。

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 冷启动单个环境 ≤ 5 秒；列表 200 个环境时滚动不掉帧 |
| 资源 | 单环境常驻内存 ≤ 350 MB；16 GB 机器默认并发上限 8 |
| 可靠性 | 异常退出后重启，环境配置零丢失；代理密码可正确解密 |
| 兼容性 | macOS 13+（Intel / Apple Silicon）；Windows 10+ 为后续目标 |
| 可维护性 | 引擎层可替换：新增引擎不应改动业务层代码 |
| 可观测性 | 所有启动失败必须落到日志，且带可读原因，不允许"静默失败" |

## 6. 数据与隐私

- **全部数据本地存储**，默认目录 `~/Library/Application Support/FoxBox/`，不上传任何服务端
- Cookie / 浏览历史属于高度敏感数据：不做任何形式的外发、不写入日志、导出功能默认排除
- 代理密码使用系统钥匙串加密，日志中对密码与 Token 做掩码
- 删除环境时，user-data 目录一并清理（回收站内的保留原目录，彻底删除才清理）

## 8. 合规与可接受使用（硬性约束）

本工具的定位是**帮助用户管理自己拥有或已获授权运营的账号**，降低误关联带来的运营风险。以下用途明确禁止，且不在产品能力设计范围内：

- 批量注册、养号、虚假身份伪造
- 绕过平台因违规而施加的封禁
- 爬取需登录的他人数据、薅羊毛、欺诈、垃圾信息投放
- 任何违反目标平台服务条款或当地法律的行为

产品侧的技术约束（而非仅口头声明）：

- 不内置代理/IP 资源，不提供"一键换 IP 池"
- 不提供账号批量注册、自动过验证码能力
- 不提供指纹"随机洗白"功能——指纹必须固化，这既是技术要求也是合规要求
